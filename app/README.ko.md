# IR 피드백 외부 모듈

기존 BinderJet 프로그램의 소스·실행 파일을 바꾸지 않고, 실행 창을 찾아 `T_recoating`과 층 정보를 읽는 별도 프로그램입니다. M1/S3 선택, 자동 창 검색, **연결 / 연결 해제**, Excel 알고리즘 계산 미리보기와 **기존 Sequences IR 입력 → Save 경로를 이용한 UI 자동 적용**을 제공합니다.

UI 자동 적용은 사용자가 실제 운전에서 사용하는 기존 IR 입력·Save 절차에 한정됩니다. 기본 시작 모드는 조회이며, **UI 자동 적용을 직접 선택하고 연결해야** 변경을 시작합니다. 히터 ON/OFF, Expert 화면, COM 포트 또는 공정 시작·정지 명령은 조작하지 않습니다.

## 실행과 연결

배포 폴더를 통째로 유지하고 `IRFeedback.exe`를 실행합니다. 동봉된 Python/Tk 런타임을 사용하므로 별도 설치, 환경변수, PID 입력 또는 설정 파일 준비는 필요하지 않습니다.

Windows 64비트에서 원본 프로그램과 같은 사용자 계정·권한 수준으로 실행합니다. 원본이 관리자 권한으로 실행 중이면 외부 모듈의 실행 권한도 맞춰 주세요.

1. 평소처럼 기존 BinderJet 프로그램을 실행합니다.
2. 외부 모듈에서 M1 또는 S3를 선택합니다. 실행 중인 BinderJet 창은 자동 검색되며 **다시 검색**으로 갱신할 수 있습니다.
3. 검색한 창을 선택하고 **연결**을 누릅니다. 시작 모드는 **조회**입니다.
4. 조회·미리보기만 사용할 때는 원본의 Process 표를 한 번 열어 생성해 주세요. 자동 적용은 연결 준비에서 필요한 화면을 생성·확인합니다. 이후에는 다른 탭을 보거나 원본을 최소화해도 새 T_recoating을 읽습니다. 조회는 설정을 저장하지 않습니다.
5. 계산 결과만 보려면 연결 해제 후 **계산 미리보기**를 선택하고 다시 연결합니다. 실제 기존 UI에 적용하려면 **UI 자동 적용**을 선택합니다. 목표 온도는 연결 전에 화면에서 변경할 수 있습니다.
6. **연결 해제**는 외부 읽기·계산·추가 적용을 종료합니다. 원본 프로그램을 종료하거나 기존 가열 ON/OFF를 변경하지 않으며, 마지막으로 저장한 설정을 임의로 되돌리지 않습니다.

창 제목만으로 M1/S3를 확정할 수 없는 공통 Operator 창은 **장비 미확인**으로 표시하며 조회·미리보기만 허용합니다. 연결 중에는 장비·모드·설정 입력을 잠가 이력이 섞이지 않도록 합니다.

## 표시하는 값과 계산 시점

- **현재 층 / T_recoating**: 기존 화면에서 읽을 수 있는 최신 리코팅 후 온도입니다.
- **현재 설정 읽기**: 원본의 저장된 IR 설정값이며, 자동 적용 전 Sequences 표시값과 대조합니다. 물리 센서로 검증한 출력 측정값을 의미하지 않습니다.
- **계산 권장값**: 원본 Excel 계산식이 산출한 값입니다. 미리보기에서는 장비로 보내지 않습니다.
- **공통 IR 설정**: 원본 UI가 하나의 공통 설정을 사용하는 경우 두 행에 공통 설정임을 명시합니다. 독립 채널 제어로 표시하지 않습니다.

연결할 때 이미 있던 과거 표의 값은 표시만 합니다. 연결 이후 **새 `T_recoating` 기록을 받을 때** 층별 계산을 한 번 수행하고 다음 기록까지 결과를 유지합니다. UI 자동 적용에서는 권장값이 현재 설정과 달라질 때만 기존 Save를 한 번 수행합니다. 같은 행을 반복 조회하거나 기존 값을 유지할 때는 저장을 반복하지 않습니다. 추가 온도 측정이나 추가 IR 가열 구간을 만들지 않습니다.

첫 두 새 관찰에서는 설정을 유지합니다. 실제로 읽은 설정 변화, 층 누락·역행 또는 재연결에 따라 학습 이력을 초기화하거나 대기합니다. 입력이 불완전하면 값을 임의로 채워 계산하지 않습니다.

일시정지·IDLE 또는 상태 미확인 동안에는 학습 이력을 초기화하고 계산·Save를 하지 않습니다. AUTO/RUNNING 재개 후에도 기존 행을 새 입력으로 재사용하지 않고, 그때부터 새 `T_recoating` 기록을 기다립니다.

화면 값은 최소 약 1초 간격으로 읽으며 원본 표 자체도 약 1초 간격으로 표시를 갱신합니다. 창 상태와 Windows 응답에 따라 더 늦어질 수 있습니다. 원본 프로그램에 통신 API를 추가하지 않는 방식이므로 하드 실시간 제어·완전한 데이터 수집은 보장하지 않습니다.

## UI 자동 적용 중 화면 사용

연결 준비 시 한 번 **Sequences 설정 확인 → Process 표 준비**를 진행합니다. 최소화된 원본을 복원하거나 전면으로 가져오지는 않습니다. 준비가 끝나면 사용자가 원하는 다른 탭을 보거나 최소화할 수 있습니다. 실행 중에는 화면 전환·포커스 이동 없이 **새 T_recoating 확인 → 숨겨진 기존 IR 입력값 변경 → 기존 Save 이벤트 1회 → UI·저장 파일 확인** 순서로 진행합니다.

원본의 표는 다른 탭으로 이동하면 타이머가 멈춥니다. 외부 모듈은 숨겨진 표의 기존 Scroll 이벤트를 한 행 이동·복귀로 실행해 원본의 최신 상태를 다시 읽습니다. 실제 스크롤 이동·복귀와 응답을 확인한 뒤에만 표의 값을 사용합니다. 새 층이 현재 캐시 범위를 벗어나면 제한된 횟수의 기존 스크롤로 추종합니다. 창 복원, 활성 탭 변경, 전역 키보드·마우스 입력은 하지 않습니다.

다른 탭을 보는 것은 가능합니다. 설정을 수동 편집하면 자동 Save와 충돌하므로 적용을 중단합니다. 연결 전 미저장 Sequence 편집값도 버리거나 저장하지 않고 연결을 거부합니다. 탭과 무관하게 장비 종류, 컨트롤 소유 관계, AUTO/RUNNING, 현재 층·온도, 모든 Sequence 입력과 기존 저장값을 다시 확인합니다.

표의 스크롤 범위가 없는 매우 짧은 작업에서는 숨겨진 표의 갱신을 확인할 수 없어 중단합니다. 이 경우 Process 표를 보이는 상태로 사용해야 합니다. 원본 UI가 응답하지 않거나 컨트롤이 사라진 경우에도 과거 캐시값으로 계산하거나 저장을 재시도하지 않습니다. 원본 프로세스와 Windows 세션이 계속 실행 중이어야 하며 절전 중에는 동작하지 않습니다.

Save 후 응답 시간 초과나 읽기 확인 실패로 저장 여부를 알 수 없으면 **재저장·복원·히터 정지를 시도하지 않고 중단하여 확인을 요청**합니다. 기존 화면에서 결과를 확인한 뒤 사용자가 재연결해야 합니다.

## 원본 Excel과 검증

알고리즘은 [Notion IR 출력 제어 자료](https://app.notion.com/p/3f105e94a225801c9cd6c70784c2d9ec)의 `IR_출력제어_수동테스트_랜덤패턴_80층.xlsx` 수식을 옮겼습니다. 원본 SHA-256:

`2dbdff1057ab0a2f0bbe539b77ffb71782f10daf61f8d111236d6f5585e16a94`

랜덤 80층과 입력 예시 67행에서 권장 출력 D, k/α/β/G와 숫자 보조 열 55개, **총 8,085개 결과**를 Excel의 저장된 결과와 비교합니다. 입력 예시는 α 변경과 두 번의 초기화를 포함합니다. 별도 테스트에서는 β 증감·상한/하한, 중복 작업자 방지, 늦은 이벤트 무시, 해제·종료, 제어 불가 시 출력 조작 없음도 확인합니다.

원본 기본 목표 온도는 65°C이며 한 번의 증감은 최대 5%p입니다. 동봉한 원본 설정을 자동으로 읽습니다. **S3 원본 시험의 수식 재현이며 M1/S3 실장비 안전성 검증은 아닙니다.** 모의 어댑터와 별도 Windows 시험 창으로 검사했으며, 실제 장비에 IR 변경을 보내는 검사는 별도로 확인해야 합니다. 선택 설정 파일은 고급 사용용이며 일반 실행에 필요하지 않습니다.

현재 IR 설정의 소수 부분은 유지합니다. 예를 들어 62.5%에서 5%p 내림은 57.5%이며, 정수로 잘라 전달하지 않습니다. 원본 .NET 저장 과정의 미세한 수치 반올림은 절대오차 `1e-9` 이내에서 동일하게 취급합니다.

배포 폴더에서 동봉 런타임으로 개발용 검사를 실행할 수 있습니다. 원본 프로그램이나 실제 장비에는 연결하지 않습니다.

```powershell
cd app
..\runtime\python.exe -E -s -B -m unittest -v test_layer_algorithm test_session test_windows_ui_adapter test_sequence_persistence test_sequence_field_audit

```

## 안정성과 제한

UI 읽기·계산·설정 적용은 별도 작업자에서 수행합니다. 화면에는 제한된 이벤트 큐로 전달하며 상태 기록은 약 100줄로 제한합니다. 중복 연결과 같은 Windows 세션에서의 외부 모듈 중복 실행을 차단합니다. 연결 해제·창 닫기는 UI 스레드에서 작업자 종료를 기다리며 멈추지 않으며, 닫을 때 정리 시간을 최대 4초 허용합니다.

컨트롤 식별은 개별 입력/버튼 HWND의 AutomationId만 확인하며, 표/폼 전체의 UIA 트리나 화면 밖 행의 Bounds를 조회하지 않습니다. 값 읽기, 체크 상태 확인, IR 입력과 Save, 화면 전환과 현재층 추종은 검증한 HWND에 대한 Windows 메시지/MSAA 경로를 사용합니다. 이 구분은 .NET 표 접근성 코드의 화면 밖 행 계산으로 UI가 오래 멈출 수 있는 경로를 피하기 위한 것입니다.

도우미가 제한 시간 내 응답하지 않으면 외부 모듈이 생성한 도우미만 종료합니다. 원본 BinderJet 소스·실행 파일·프로세스 메모리·COM 포트·모션/히터 통신에는 개입하지 않습니다. 설정 변경은 사용자가 선택한 UI 자동 적용의 기존 IR 입력·Save에만 한정합니다. 오류 시 자동으로 재접속하거나 제어를 시작하지 않습니다. 예외 기록은 외부 모듈의 `app/IR-module-error.log`에 크기를 제한해 저장합니다.

UI에 저장한 IR 설정과 실제 히터 출력의 일치 여부는 원본 프로그램의 공정 구간·층별 설정·장비 상태에 따라 달라집니다. 기존 가열 ON/OFF와 장비 안전 기능은 원본 프로그램이 계속 담당합니다.

현재 보관된 S3 설정 파일에는 소스 매핑의 일부 항목이 없어 해당 설정에서는 자동 적용을 거부합니다. 누락 항목을 임의로 생성하지 않습니다. 실제 S3 환경의 기존 설정이 확인되어야 합니다. 새 T_recoating 행도 물리 센서 읽기의 성공을 독립적으로 증명하지는 않습니다. 자세한 제한과 시험 결과는 배포 폴더의 `VALIDATION.ko.md`를 확인하세요.
