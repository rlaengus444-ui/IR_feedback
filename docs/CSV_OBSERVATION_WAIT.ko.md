# 258층 사례: CSV 갱신 중 연결 종료 수정

`2026.10.30-csv-wait.1`은 검증 후보입니다. 기존 공개 EXE `2026.10.29-auto-slice.1`에는 이 수정이 없습니다. 이 문서는 코드 수정과 오프라인 재현 결과이며 실제 장비 적용 승인이 아닙니다.

## 실제 파일에서 확인한 사실

제공된 `LayerDatasheet_20261029_191426.csv`는 1~258층 258행으로, 층·시각·온도·이미지 파일 번호에 이상이 없었습니다. `층별_IR_온도.csv`는 41~256층 216행이며 해당 원본 온도와 모두 일치합니다. BJT의 Layer 259는 다음 시작 층이며, 258층 완료와 충돌하지 않습니다.

## 원인과 확정할 수 없는 부분

화면의 정확한 오류 문구는 IR 입력 전 재검증에서 CSV 토큰이 없거나, 관찰했던 완료 행과 최신 행이 달라졌을 때 발생합니다. 기존 코드는 이를 종료 예외 `ControlUnavailable`로 전달했고 세션이 연결을 종료했습니다. 정상적인 파일 갱신도 이 경로에 들어갈 수 있었습니다.

실제 256~258층 원본 바이트를 임시 파일에 순차 기록해 재현했습니다. 257층 계산 도중 258층의 전체 행 또는 부분 행이 추가되면 기존 버전은 화면과 같은 오류로 종료되고 직전 표시인 256층에 남았습니다. 수정본은 동일 조건에서 258층까지 관찰을 갱신하며 연결을 유지했습니다. 오래된 결정의 입력·Save와 설정 복구 탐색은 발생하지 않았습니다. Excel 계산과 장비 UI는 모의 구현이며 실제 COM이나 BJT를 실행한 시험이 아닙니다.

종료 당시 상태 기록·장비 로그·실행 ZIP 버전은 제공되지 않았습니다. 당시 계기가 부분 쓰기였는지, 다음 완료 행 수신이었는지, 정확한 예외 시각이 언제였는지는 확정하지 않습니다. 최종 CSV만으로 쓰기 도중의 파일 상태를 복원할 수는 없습니다.

## 변경 동작

- 같은 작업의 기록 중 또는 완료 행 변경은 전용 대기 예외로 처리합니다. 연결·CSV 조회·그래프를 유지합니다.
- 해당 계산과 제어 이력을 폐기하고 캐시를 지워 실제 CSV를 다시 읽습니다. 다음 유효 관찰은 기준값으로만 사용하고, 그 뒤 새로 수신한 다른 층부터 계산합니다. 기존 명령을 재시도하지 않습니다.
- 설정 변경 복구와 구분하므로 이 대기를 이유로 Sequences 탭을 열거나 설정을 재저장하지 않습니다.
- Python 사전 검증과 Windows 도우미의 명시적인 파일 크기·시각·내용 변경을 모두 처리합니다. 원인 불명 도우미 오류는 계속 종료 오류입니다.
- IR 편집 또는 Save 마커가 있으면 결과 불명확으로 종료합니다. CSV 대기 예외라도 이 보호를 우회하지 못합니다.
- 잘못된 작업·층·시간, 비활성 온도 -1, 오래된 측정 및 손상된 토큰에 대한 기존 차단을 유지합니다. 계산식·시트·입출력 제한은 변경하지 않습니다.
