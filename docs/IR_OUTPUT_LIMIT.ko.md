# 최대 IR 출력 변경

`2026.11.03-live-cap.1`은 연결 전과 연결 중 최대 IR 출력을 0~100%로 지정합니다. 기본값은 100%이며 소수도 가능합니다. 연결 중에는 값을 입력하고 **상한 적용**을 누릅니다. 입력만으로 값이 바뀌지는 않습니다. 버튼은 다음 유효한 새 층에서 사용할 상한을 요청하며 즉시 IR을 저장하지 않습니다. 연결·CSV·그래프 기록은 유지합니다.

## 현재 출력보다 낮춘 경우

80%에서 상한을 60%로 바꾸면 유효한 새 층마다 75→70→65→60% 순으로 내려갑니다. 기본 JSON의 변경 폭이 2%p이면 78→76→…→60%로 낮춥니다. 이 정책은 연결 시 설정한 상한에도 동일하게 적용합니다. 상한에 도달하기 전에는 출력이 요청 상한보다 높을 수 있으며 화면에 단계 감속 상태를 표시합니다. 같은 층을 반복 저장하지 않습니다. 유효한 센서·CSV·작업·설정과 정상 계산 결과가 없으면 감속을 실행하지 않습니다.

기본 알고리즘은 원래 JSON의 최소·최대 출력과 최대 변경 폭을 보존합니다. 유효 상한은 사용자 요청과 JSON 최대값 중 작은 값입니다. JSON 최소값보다 낮은 요청은 거부하고 이전 요청과 적용값을 유지합니다. 현재 실제 설정이 원래 JSON 허용 범위 밖이면 자동으로 수정하지 않고 재확인을 기다립니다. Excel은 원시 수식 결과가 유효한 0~100% 숫자인지 검증한 뒤 상한과 최대 5%p 제한을 적용합니다. 수식 자체와 이미 확정된 행은 유지하며 워크북 알고리즘이 사용자 상한을 입력받는 것은 아닙니다.

## 계산·저장 도중 변경

요청한 상한, 적용 중인 상한, 다음 새 층 대기, 단계 감속과 진행 중인 저장을 구분해 표시합니다. 계산 중 상한이 바뀌거나 A→B→A로 돌아와도 이전 상한의 미확정 결과는 저장하지 않습니다. 대기 중의 완료 이력은 상한 변경만으로 초기화하지 않습니다. 미확정 작업이 취소될 때에는 기존 이력 재확인 보호를 적용합니다.

실제 저장 요청 직전에 상한 변경 이력을 다시 확인합니다. 그 승인 전에 바뀌면 입력·Save를 시작하지 않습니다. 승인 뒤 이미 진행 중인 저장은 완료될 수 있으며 새 요청은 다음 저장과 새 층에 반영합니다. 이때 앞 채널의 확인된 Save는 보존하고, 새 요청 전 계산으로 다음 채널을 저장하지 않습니다. 저장 결과가 불명확하면 자동 재저장·원복을 하지 않는 기존 보호를 유지합니다. 승인 중에도 상한 입력을 막는 긴 잠금을 잡지 않습니다.

## 설정 저장과 검증 범위

접수된 값은 `%LOCALAPPDATA%/IRFeedback/ir-output-limit.json`에 저장합니다. 연결 중 종료 시에는 **상한 적용**으로 접수된 값을 보관하며, 아직 적용을 누르지 않은 입력 초안은 다음 실행의 값으로 덮어쓰지 않습니다. 설정 파일 저장에 실패해도 접수된 실행 중 요청을 되돌리지 않고 상태 기록에 오류를 남깁니다. 로컬 설정 파일은 기존 원자 저장 방식을 사용하므로 디스크가 느리면 화면이 잠시 기다릴 수 있습니다. 제어 작업은 별도 스레드에서 계속하며 이 저장 때문에 native/Excel 작업이나 승인 잠금을 기다리지 않습니다.

원본 창 접근과 백그라운드·최소화 동작, 수동 이미지 입력, CSV·두 PNG 저장을 유지합니다. Windows 및 합성 시험과 독립 검토는 [배포 페이지](https://github.com/rlaengus444-ui/IR_feedback/releases/tag/2026.11.03-live-cap.1)에 기록합니다. 실제 Excel COM·BJT·센서·PLC·램프·잠금·절전·장시간 열 제어는 미검증입니다. 정상 범위의 오래된 센서값은 CSV만으로 감지할 수 없습니다. 최종 알고리즘 승인과 실제 장비 적용은 보류합니다.
