# 2026.10.28-slice.2 — 다운로드 DLL 로딩 수정 후보

이 변경은 사용자가 보고한 `UiaBridge.dll` 로딩 오류 `0x80131515`에 대응합니다. 이전 검증용 ZIP과 계산시트·알고리즘은 보존합니다. 기존300층 모의 계산 및 G·알파·베타 수식에는 변경이 없습니다.

## 변경

기존 PowerShell `Add-Type -Path`는 다운로드 표시가 붙은 DLL을 .NET에서 거부할 수 있습니다. 새 로더는 배포 DLL의 최대1 MiB 한도 내 바이트를 읽고, 고정 SHA-256과 비교한 동일 바이트 배열을 로드합니다. Windows/.NET 기본 어셈블리 이외의 경로를 추가 탐색하지 않습니다. 다운로드 표시를 삭제하거나 Windows·PowerShell의 전역 정책을 변경하지 않습니다.

검증 대상 DLL은20,992바이트, SHA-256 `7d0d94474a500d0cbfa5725b9e1e385682b32266ac2e862d09048f8de98f4a72`입니다. 파일 누락·크기 초과·해시 불일치는 로드 전에 중단합니다. DLL을 다시 빌드하면 코드 검토 후 고정 해시도 갱신해야 합니다.

## 검증 절차와 현재 상태

수정 전 실제 Sol Max 설계 검토를 받았습니다. Windows 자동 검증은 ZIP에서 추출한 내장 Python과 Windows PowerShell을 사용합니다. DLL에 `Zone.Identifier / ZoneId=3`을 붙이고 기존 로더의 오류 재현 여부, 새 로더의 실제 장비창 검색, 별도 UIAutomation 초기화, 변조·크기 초과·누락 거부 및 다운로드 표시 보존을 확인합니다. 원래 DLL 바이트는 시험 후 복원합니다. EXE 주 창 표시만으로 DLL 로딩 성공을 간주하지 않습니다.

이 문서는 검증 절차를 설명하며 실행 성공을 미리 기록하지 않습니다. 실제 결과와 해당 ZIP 해시는 Actions의 별도 결과 파일과 후속 독립 검토 기록을 확인하세요. 이전버전 결과는 `docs/SLICE_VALIDATION.ko.md`에 보존합니다.

## 유지되는 한계

Microsoft Excel COM 실제 연동은 미검증입니다. 시트 수식의 LibreOffice 교차검증은 Excel COM 검증을 대신하지 않습니다. 열 모델의300층 모의 결과는 실제 장비 예측이나 실제 센서·PLC·램프 검증이 아닙니다. 제어 알고리즘 최종 승인과 실제 장비 적용은 계속 보류하며, 검증용 배포로만 구분합니다.
