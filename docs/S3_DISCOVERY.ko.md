# S3 연결 준비 오류 수정 · 평가용

버전 `2026.10.28-s3.1`은 기존 `slice.2`의 장비 컨트롤 탐색을 수정합니다. 내장 G·알파·베타 알고리즘, Excel 연결 계약, 외부 계산시트 두 종류와 CSV·IR 적용 보호 조건은 변경하지 않습니다. 실제 장비 적용과 제어 알고리즘 최종 승인은 보류합니다.

## 원인과 수정

`[enter_sequence] IdentifyMachine ... Native control discovery exceeds the 900-child bound`는 장비명 확인 단계에서 발생합니다. 기존 코드는 숨겨진 화면과 관련 없는 컨테이너까지 모든 자식 HWND를 900개 제한에 포함했습니다. S3 화면에 이러한 항목이 많으면 장비명이나 Sequences 버튼을 확인하기 전에 중단됐습니다.

새 코드는 전체 HWND 방문 수(최대 16,384)와 실제 후보 컨트롤 수(최대 900)를 분리합니다. 장비명·버튼 탐색은 보이는 STATIC/BUTTON, 메타데이터는 보이는 EDIT/STATIC/BUTTON만 대상으로 합니다. 비활성화된 입력도 보이는 항목이면 설정 기준값 확인에 포함합니다. 숨겨진 항목과 지원하지 않는 컨테이너에는 텍스트·UIA 메타데이터를 요청하지 않습니다.

전체 제한 내 탐색을 마친 뒤 장비명·버튼을 고르므로, 뒤에 나타난 상충 장비명이나 중복 버튼을 무시하지 않습니다. 방문·후보 상한을 넘으면 부분 결과로 연결하지 않고 중단합니다. PID·창 소유권·가시성·클래스를 다시 확인한 뒤 읽습니다. Process 표의 접근성 트리·스크롤·Bounds를 탐색하지 않습니다.

DLL은 Windows에서 다시 컴파일했으며 21,504바이트, SHA-256 `181d32dd5b13cee276553f6dd2347227fe9b44c288e717d0a399ec57d47b700f`입니다. 동일 바이트를 고정 해시로 확인한 뒤 메모리에서 로드하는 기존 다운로드 DLL 보호 방식을 유지합니다.

## 설치와 시트 선택

기존 외부 모듈을 닫고 ZIP 전체를 새 폴더에 압축 해제한 뒤 `IRFeedback.exe`를 실행합니다. DLL 하나만 다른 버전과 섞지 마세요. 설정 JSON과 runtime 폴더를 함께 유지합니다.

이미지 회복제어 / 파우더층 제어·분사층 고정 엑셀은 기존 전달 파일을 계속 사용합니다. `Excel 수식 파일 → 찾아보기`로 직접 선택하고 이미지 시작셀을 `BL13`으로 지정합니다. 내장 시트 저장 버튼은 이전 참고열 전용 시트를 생성합니다.

## 검증 상태

검증에는 연결된 실제 장비가 없는 Windows 환경의 별도 모의 창을 사용합니다. 숨겨진 HWND 1,200개 초과와 보이는 비대상 HWND 1,200개 초과, 기존 DLL 오류 재현, 장비명·버튼·ID 중복, 900/901 후보 경계, 비활성화 입력 보존, 잘못된 PID와 변경된 핸들 거부를 확인합니다. 실행 결과는 Actions의 `discovery.json`, `tests.txt`, `bridge.json`, `csv-guard.json`과 별도 독립 검토 기록에 보존합니다. 시험을 실행하기 전에 성공한 것으로 기록하지 않습니다.

Microsoft Excel COM과 실제 S3 연결·센서·PLC·램프 출력은 이번 모의 검증에 포함되지 않습니다. 16,384개 초과의 실제 HWND 생성 시험도 수행 여부를 구분해 기록합니다. 기존 측정 시점·센서 신뢰성 한계는 유지됩니다.
